# Темы для EDT 2026.1.3: анализ и предложение решения

Дата исследования: **13 октября 2026 года**.

Статус: подход согласован пользователем 13 октября 2026 года. Подготовлен [план реализации](../superpowers/plans/2026-10-13-edt-themes-mvp.md). Исходники и прототип не создавались. Установка плагина и переключение палитры в работающей EDT не проверены. [Локальные факты](2026-10-13-installed-platform.md) имеют приоритет над предварительными предположениями.

## 1. Задача и вывод

Нужен устанавливаемый плагин, позволяющий выбирать привычные палитры IDE для рабочего пространства EDT. Для первого MVP предлагаются **Darcula** и **Monokai**. Под темой понимаются цвета интерфейса и кода; перенос геометрии, поведения и набора иконок другой IDE в задачу не входит.

Задача имеет техническую основу: EDT поддерживает расширения Eclipse, а Eclipse предоставляет механизмы CSS-тем и именованных цветов. Но обещать полную совместимость конкретного плагина до проверки EDT 2026.1.3 нельзя.

**Рекомендуемый вариант после локальной проверки:** самостоятельный Eclipse/OSGi-плагин с профилями Darcula и Monokai поверх штатной тёмной темы EDT, наборами именованных цветов и адаптером настроек редактора. Поставка — feature и локальный p2 ZIP; никаких изменений JAR вендора. Два самостоятельных CSS theme IDs больше не рекомендуются для первого MVP: EDT распознаёт тёмную тему по точному стандартному ID.

Следующий предварительный шаг — проверить применение и приоритеты именованных цветов и BSL preferences в тестовой EDT. Выбор Darcula/Monokai предлагается на странице плагина; стандартный выбор темы остаётся Dark.

## 3. Границы достоверности и версии

Установка пользователя исследована статически: Eclipse 4.30.0, SWT 3.124.200, Xtext UI 2.33.0, требования Java 17. Axiom JDK 17.0.18 установлен и доступен. Часть BSL preference keys и точная проверка dark ID подтверждены чтением файлов/байткода. Фактическая JVM запущенной EDT и применение цветов в интерфейсе не проверены. [Подробности](2026-10-13-installed-platform.md).

Приведённое пользователем руководство полезно для устройства плагина, но страницы среды и target platform содержат ссылки на более старые выпуски. В актуальном `master` демонстрационного проекта target уже указывает на EDT 2026.2 и Eclipse 2025-12; его BOM задаёт Java 25. Поэтому ни старую инструкцию, ни текущий пример нельзя переносить без проверки. [Настройка среды](https://edt.1c.ru/dev/ru/docs/plugins/project/env-setup/), [target примера](https://github.com/1C-Company/dt-example-plugins/blob/master/targets/default/default.target), [BOM примера](https://github.com/1C-Company/dt-example-plugins/blob/master/bom/pom.xml).

Документация Eclipse по ссылкам `latest` подтверждает существование механизмов, но финальную реализацию нужно сверять со схемами и API именно установленного target.

Доступный JavaDoc EDT 2024.2 описывает `BslHighlightingConfiguration`, реализующий Xtext `IHighlightingConfiguration`. В нём представлены стили ключевых слов, строк, комментариев, чисел, встроенных конструкций, препроцессора и других категорий. Это полезный ориентир для инвентаризации, а не подтверждение неизменности контрактов 2026.1.3. [JavaDoc BSL](https://edt.1c.ru/dev/edt/2024.2/apidocs/com/_1c/g5/v8/dt/bsl/ui/syntaxcoloring/BslHighlightingConfiguration.html).

Попытка прочитать p2 metadata предполагаемого канала `ruby/2026.1/` не дала результата через доступные инструменты. Канал не подтверждён как источник точных артефактов 2026.1.3. Не следует считать эту неудачу доказательством отсутствия репозитория.

## 4. Почему одной CSS недостаточно

| Слой | Что меняет | Предлагаемый механизм |
|---|---|---|
| Workbench/SWT | Фон, текст, вкладки, деревья, таблицы, панели, части диалогов | e4 CSS theme |
| Именованные цвета | Цвета редакторов, вспомогательных панелей и компонентов 1С | `org.eclipse.ui.themes`, `colorOverride`, ассоциация тем |
| Подсветка языка | Цвета и начертание лексических и семантических категорий BSL | Сначала штатные определения цветов; при неполном покрытии — проверенный адаптер настроек BSL/Xtext |
| Отдельные подсистемы | Консоль, сравнение, всплывающие подсказки, язык запросов | Свои registry/preferences, только после инвентаризации |
| Предпросмотр прикладного интерфейса | Содержимое формы и макетов | Сохранить прикладное оформление |

Eclipse связывает CSS theme и legacy Colors and Fonts theme через `themeAssociation`. При смене legacy theme workbench обновляет JFace-реестры. Это делает согласованную палитру интерфейса и именованных цветов возможной. [Схема CSS-тем](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.isv/reference/extension-points/org_eclipse_e4_ui_css_swt_theme.html), [IThemeManager](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.isv/reference/api/org/eclipse/ui/themes/IThemeManager.html).

Xtext описывает два уровня подсветки — лексический и семантический — и отдельные настройки зарегистрированных стилей. Значит, перекрасить фон `StyledText` недостаточно для корректной подсветки языка. [Документация Xtext, Syntax Coloring](https://eclipse.dev/Xtext/documentation/310_eclipse_support.html#syntax-coloring).

Не предлагается заменять парсер, semantic highlighting calculator или Guice bindings языка: задача касается цветов уже существующей подсветки.

## 5. Возможные подходы

| Подход | Преимущества | Ограничения | Решение |
|---|---|---|---|
| Только пресеты подсветки BSL поверх штатной тёмной EDT | Самый небольшой объём, сохранение адаптаций вендора | Панели и вкладки не получают самостоятельного оформления Darcula/Monokai | Резервный сокращённый вариант, если полный UI окажется сложнее ожидаемого |
| Профили палитр интерфейса + именованные цвета EDT + адаптер редакторов поверх штатной Dark | Сохраняет adaptations и выбор dark icons EDT; позволяет менять UI и BSL | Своя страница выбора палитры, нужна проверка приоритетов настроек | **Рекомендуется после локальной проверки** |
| Готовый Eclipse-плагин темы с доработкой под EDT | Можно использовать как ориентир или основу | Требуется адаптация BSL/EDT, проверка версий и лицензии выбранных ресурсов | Не выбирать основной зависимостью MVP |

[Eclipse Color Theme](https://github.com/eclipse-color-theme/eclipse-color-theme) применяет общую палитру через специфические настройки поддерживаемых редакторов. В опубликованном списке поддержки нет BSL/EDT; поддержка Java или SQL не означает поддержку редакторов 1С.

[MoonRise](https://github.com/guari/eclipse-ui-theme) иллюстрирует CSS-темизацию интерфейса, но его README отделяет syntax highlighting от UI theme и перечисляет проверки на старых выпусках Eclipse. Это пример архитектуры, а не доказательство совместимости с EDT 2026.1.3.

## 6. Предлагаемая архитектура

### 6.1. Состав

Для MVP достаточно одного собственного UI bundle. Внутри него разделить четыре обязанности:

1. **Каталог палитр:** ID, название, цвета интерфейса и смысловые роли подсветки. Darcula и Monokai — отдельные данные, без дублирования логики применения.
2. **Оформление Eclipse:** штатная Dark EDT как основа, палитры именованных цветов и только необходимые дополнительные CSS-правила с проверенным жизненным циклом.
3. **Адаптер EDT:** карта смысловых ролей в реальные color IDs и, при необходимости, preference keys конкретной версии EDT.
4. **Применение и восстановление:** проверка совместимости, сохранение исходного состояния, применение, обработка смены темы и возврат настроек.

Feature включает этот bundle; repository формирует p2 ZIP. Дополнительный bundle адаптера имеет смысл позже, если появится поддержка нескольких существенно различающихся версий EDT.

Ориентир структуры — стандартные bundles/features/repositories/targets из примера вендора; копировать все демонстрационные модули не требуется. [Структура проекта](https://edt.1c.ru/dev/ru/docs/plugins/project/project-structure/).

### 6.2. Регистрация и применение

Для MVP сохранять стандартный CSS dark ID. Применять профили именованных цветов и настройки BSL через проверенный адаптер; поддерживать сохранение и восстановление значений. Отдельный legacy Colors and Fonts theme допустим только после проверки, что штатные CSS preferences его не перезаписывают. Не менять глобальную `themeAssociation` стандартной Dark для всех пользователей.

**Импорт CSS не является наследованием всей тёмной темы.** Stylesheets других плагинов, привязанные к стандартному dark theme ID, не обязаны применяться к нашему ID. Аналогично, компоненты EDT могут выбирать dark palette по собственному признаку. Нужно изучить contributions в целевой установке и проверить ключевые экраны.

Локально установлено: `DtThemeUtil.isDarkThemeActive()` проверяет равенство стандартному dark ID; `getIconPath` использует этот результат. Поэтому предложены профили поверх штатной Dark. Это по-прежнему палитры UI и BSL, а не только пресеты подсветки. Самостоятельные CSS-темы с отдельными IDs потребуют дополнительного решения для adaptations и иконок и откладываются за MVP.

`IThemeEngine` позволяет получать активную тему, переключать её с сохранением выбора и повторно применять стили. Наличие этих методов не означает, что все компоненты EDT обновятся без перезапуска. [API IThemeEngine](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.isv/reference/api/org/eclipse/e4/ui/css/swt/theme/IThemeEngine.html).

Предпочтительны декларативные color overrides. Прямое изменение `ColorRegistry` допустимо лишь как проверенная часть адаптера: сам реестр управляет объектами Color и выдаёт уведомления, но вызов `put` не решает автоматически вопрос постоянного хранения. [ColorRegistry](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.isv/reference/api/org/eclipse/jface/resource/ColorRegistry.html).

### 6.3. Пользовательский сценарий

Предлагается небольшая страница «Темы EDT» под «Общие → Внешний вид»:

- выбор Darcula или Monokai;
- опция применения палитры BSL, по умолчанию включённая;
- действие «Применить»;
- действие «Восстановить исходное оформление»;
- сообщение о необходимости перезапуска для полного применения.

Darcula и Monokai выбираются на странице плагина; стандартный селектор Eclipse показывает Dark. Координатор обрабатывает смену штатной темы, исключает рекурсивные события и не навязывает профиль при каждой активации редактора.

При установке палитра не включается автоматически. При выборе сторонней/штатной темы управление плагина прекращается и восстанавливаются затронутые им значения по правилам ниже.

### 6.4. Настройки и восстановление

Перед первым применением сохранить CSS theme ID, legacy theme ID и только значения, которые плагин действительно меняет. Для preferences сохранять не только эффективное значение, но и факт наличия явного override: восстановление отсутствующего значения отличается от записи текущего default.

При переключении Darcula → Monokai исходный снимок не перезаписывать состоянием Darcula. Изменения шрифтов, горячих клавиш, форматирования, кодировки и проектов не входят в палитру.

Сохранять исходное состояние и последние записанные значения в собственном preference node с версией формата. Перед восстановлением сравнивать текущее значение с последним применённым: если пользователь изменил его самостоятельно, не затирать такую правку автоматически. Для конфликтов предоставить явное восстановление из сохранённого снимка.

Применение включает предварительную проверку карты; при ошибке откатить уже выполненные изменения, показать понятное сообщение и записать технические детали в Error Log. Не продолжать с нечитаемой смесью палитр.

На перезапуске восстанавливать согласованное состояние без создания нового исходного снимка. Не восстанавливать настройки в обычном shutdown: это уничтожило бы выбранную тему между запусками.

Не обещать автоматическое восстановление persistent preferences при удалении bundle: надёжного сценария uninstall hook для этого здесь не установлено. В инструкции удаления предусмотреть «Восстановить исходное оформление», затем удаление feature через Installed Software.

## 7. Предлагаемые границы MVP

| Область | Ожидаемый результат |
|---|---|
| Темы | Darcula и Monokai; согласованные UI и BSL палитры |
| Платформа | EDT 2026.1.3, Windows x64; версия подтверждена проверкой |
| Основные панели | Навигатор, свойства, ошибки/проблемы, вкладки, основные диалоги |
| BSL | Фон, основной текст, выделение, текущая строка, комментарии, строки, числа, ключевые слова, директивы и прочие реально доступные категории |
| Подсказки и консоль | Читаемые фон/текст и различимые состояния; фактический охват фиксируется проверкой |
| Язык запросов | Проверить как отдельный редактор и как текст внутри BSL. Полную отдельную палитру вынести за MVP, если нужен дополнительный адаптер |
| Сохранение | Выбор сохраняется после перезапуска; смена темы и восстановление работают |
| Установка | ZIP локального p2-репозитория, содержащий собственную feature/bundle |

Для Monokai исходно предлагается приглушённый фон оболочки и характерные цветовые акценты кода. Для Darcula — серая оболочка и соответствующая палитра BSL. Конкретные RGB и эталон внешнего вида нужно согласовать до реализации; названия описывают семейства палитр, не обещают попиксельную копию чужой IDE.

За MVP: импорт тем VS Code/JetBrains, визуальный редактор палитр, расписание/следование теме ОС, новые иконки, Linux/macOS, Marketplace, автоматическая поддержка будущих EDT. Содержимое предпросмотра формы и перечисленных макетов сохраняет прикладное оформление.

## 8. Основные риски

| Риск | Как проверять/уменьшать |
|---|---|
| EDT распознаёт только стандартный dark theme ID | Проверить contributions и основные экраны до разработки полного набора CSS |
| Часть цветов меняется через реестр, часть через preferences | Создать карту по конкретному target, проверять фактический путь применения каждого семейства цветов |
| Пользовательские overrides перекрывают цвета темы | Проверить приоритеты на чистой и настроенной рабочей области; использовать ограниченные изменения и снимок |
| Нативные Windows controls и иконки плохо читаются | Визуальная проверка hover/selection/disabled/focus; исправлять поддерживаемыми средствами, фиксировать остаточные ограничения |
| Вид меняется лишь после повторного открытия или перезапуска | В MVP допустить перезапуск, показывать его необходимость |
| Плагин случайно перекрашивает прикладное содержимое | Проверить предпросмотр, MXL, графическую схему, макет СКД как отдельные исключения |
| Следующая EDT меняет IDs или API | Ограничить заявленную совместимость проверенной версией; предупреждать о неизвестном target, не записывать неизвестные keys |
| p2 предлагает обновить Eclipse ради темы | Минимизировать зависимости и проверять план установки; не поставлять replacement bundles |

## 9. Порядок последующей работы

Это последовательность исследований и реализации после отдельного поручения, а не уже выполненный план разработки.

1. **Дополнение инвентаризации:** базовые версии и dark ID уже подтверждены. Собрать полную карту цветов, проверить scopes/приоритеты preferences и legacy theme. Результат — карта совместимости с источником каждого ID.
2. **Минимальная проверка механизма:** один профиль поверх штатной Dark, один основной экран, BSL и возврат исходных значений в тестовой рабочей области. Проверить, что native theming не перезаписывает профиль.
3. **Уточнение спецификации:** зафиксировать покрытие и палитры двух тем, правила пользовательских overrides, поддерживаемые API и точные зависимости.
4. **Реализация MVP:** палитры, CSS, карта цветов, координатор, страница настройки, feature/repository.
5. **Проверка и упаковка:** чистая установка p2 ZIP в EDT 2026.1.3, матрица экранов, перезапуск, восстановление и удаление.

Если шаг 2 выявит ограничение API, пересмотреть архитектуру до полного оформления. Успешная сборка Java сама по себе не подтверждает визуальную корректность.

## 10. Критерии приёмки

- Плагин устанавливается в EDT 2026.1.3 без обновления базовой платформы.
- Обе палитры применяются к согласованным экранам и BSL; текст, выделение, ошибки и неактивные состояния остаются различимыми.
- Проверены русские и английские ключевые слова, комментарии, строки, числа, директивы компиляции, препроцессор и запрос внутри строки.
- Новые окна/редакторы после выбора темы получают согласованное оформление.
- После перезапуска тема сохраняется; многократные переключения не порождают ошибок SWT/OSGi и бесконечных событий.
- Возврат исходного оформления корректен как с явными настройками пользователя, так и без них; переключение между нашими темами не теряет исходный снимок.
- Отмена в настройках не оставляет частично применённую тему.
- Проверены обычный и повышенный масштаб Windows; точные значения и скриншоты записаны в отчёт.
- Предпросмотр формы и содержимое исключённых макетов сохраняют прикладной вид.
- Документированы установка, перезапуск, восстановление и удаление.

Автоматические проверки при реализации нужны для карты палитр, снимка/восстановления и обработки смены темы. Визуальную корректность подтверждать ручной проверкой реальной EDT. База 1С для первичной проверки CSS и редактора BSL обычно не нужна; проверки предпросмотра выполнять на небольшом тестовом проекте.

## 11. Что требуется от пользователя сейчас

Путь EDT уже получен, статическая проверка проведена. JDK 17 и Maven 3.10.0 установлены; Maven проверен с явно выбранной Java 17. Рассмотреть конкретный план реализации и выбрать способ исполнения; дополнительных установок для начала план не требует.

Список возможных инструментов и причины их выбора находится в [документе среды](../development-environment.md). Дополнительное ПО автоматически не устанавливается. Пока нет подтверждённой необходимости скачивать новый JDK или обновлять EDT.

Исследование подтверждает подход, но оставляет проверку конкретных IDs и поведения EDT для следующего этапа. Рекомендуется начать именно с этой проверки, затем реализовывать Darcula и Monokai.
