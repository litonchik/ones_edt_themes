# Уведомления об обновлениях плагина

Исследование: 06.11.2026. Это предложение следующей доработки;
плагин, опубликованная 0.1.29 и настройки рабочих EDT не изменялись.

## Как сделано в EDT-MCP

Исследован DitriXNew/EDT-MCP, master на коммите
`fc31d2e6ea876ae86673cd0f95c7594aed02c87f`.

- Собственный UpdateChecker обращается к GitHub Releases API /releases/latest,
  читает tag_name, body и html_url, сравнивает номер с установленной версией.
- Проверка работает в отдельном scheduled executor. Настройки: при запуске,
  каждый час, каждый день, никогда; исходный выбор — при запуске.
- Фактическая константа INITIAL_DELAY_MS — 10000, HTTP connect/read timeout —
  10000 мс. Комментарии ещё упоминают 60 секунд, но код использует 10 секунд.
- McpServerStartup запускает планирование; остановка освобождает executor.
- McpStatusContribution показывает «MCP New release», новую версию в tooltip
  и пункт меню Download. По нажатию открывается ReleaseNotesDialog.
- Диалог показывает изменения и кнопку Open on GitHub. Это действие открывает
  страницу релиза, само обновление в этом диалоге не устанавливается.
- Сетевая ошибка не мешает работе MCP; она записывается в журнал.

## Что уже есть в Eclipse/EDT

Штатные автоматические обновления умеют проверку в фоне, уведомление,
напоминания и переход в тот же мастер, что «Справка → Проверить обновления».
Настройка — «Установка/обновление → Автоматические обновления».
Поиск зависит от пользовательских настроек и списка доступных сайтов.
Наличие p2-сайта само по себе не гарантирует включённый автоматический поиск.

В установленной Windows EDT 2026.1.3+25 обнаружены:

- org.eclipse.equinox.p2.ui.sdk 1.3.200.v20230921-0854;
- org.eclipse.equinox.p2.ui.sdk.scheduler 1.6.100.v20230630-1506.

В EDT 2026.2.2+21 обнаружены версии 1.3.500.v20250521-0421 и
1.6.600.v20251111-1040 соответственно. В plugin.xml 2026.1.3 подтверждены
страница настроек планировщика и штатная команда
`org.eclipse.equinox.p2.ui.sdk.update`. Доступ к команде возможен через
публичный command service; импорт внутреннего UpdateHandler не требуется.
В исходниках стандартного scheduler initializer 4.30 поиск исходно выключен;
реальное значение может переопределяться продуктом или пользователем.
Рабочая EDT не запускалась и её настройки не менялись.

## Предлагаемый вариант для «Темы EDT»

Собственное уведомление только о нашем плагине, установка штатными средствами p2.
Не менять общую периодичность обновлений EDT и остальных расширений.

1. Фоновая проверка после завершения запуска, далее не чаще раза в сутки.
   Период сохранять между запусками, чтобы частые перезапуски не создавали
   повторных запросов. Кнопка «Проверить сейчас» запускает явную проверку.
2. Источник — существующий стабильный
   `https://litonchik.github.io/ones_edt_themes/repository/release.json`.
   Он публикуется вместе с реально готовым p2-сайтом и уже содержит version,
   bundle_version и release_url. Не нужен новый сервис или GitHub API-токен.
3. Номер сравнивать численно с установленным bundle. Одинаковый номер релиза
   не считать новым из-за наличия qualifier у установленной сборки.
4. При обнаружении показать немодальное уведомление:
   «Доступна новая версия Темы EDT: 0.1.31. Установлена: 0.1.30».
   Действия: «Обновить», «Что нового», «Позже»; дополнительно предусмотреть
   «Не напоминать об этой версии». Состояние показывать и на странице настроек.
5. «Обновить» открывает штатный мастер, который проверяет зависимости и
   совместимость, показывает изменения и получает согласие пользователя.
   Для установки из ZIP отдельно учесть отсутствие HTTPS-сайта в списке p2:
   при явном действии пользователя предложить его добавление, если он отсутствует.
6. В настройках отдельный флаг «Проверять обновления», по умолчанию включённый,
   и «Проверить сейчас». Настройки уведомлений независимы от палитры,
   значков, шрифта и восстановления оформления.

Сетевые обращения выполнять вне UI-потока с ограничением времени и размера
ответа, учитывать прокси EDT. При отсутствии сети фоновая проверка молчит;
ручная проверка сообщает о невозможности получить сведения. Задания отменяются
при завершении работы, уведомление не повторяется на каждом запуске.
Проверку фактической применимости обновления оставлять p2, а не обещать её
только по сравнению номеров. Доступность новой версии и возможность установить
её на конкретную EDT — разные результаты.

## Границы следующей реализации и проверки

- Номер, отсутствие обновления, пропуск версии, отложенное напоминание,
  отключённая проверка, офлайн, таймаут, прокси и повреждённый ответ.
- Поздний запуск и закрытие EDT; отсутствие блокировки UI и повторных popup.
- Установка из URL и из ZIP, отсутствующий/выключенный p2-сайт,
  недоступный/несовместимый релиз и штатный мастер обновления.
- Изолированные EDT 2026.1.2+2 / 2026.1.3+25 / 2026.2.2+21.
  Проверки новой функции после реализации, затем отдельная Cleanup.

Пока выполнено исследование исходников и локальных bundles. Уведомления и
автопроверка ещё не реализованы и не объявляются проверенными в runtime.
Для доставки собственной функции пользователям 0.1.29 потребуется одно
обновление до первой версии с уведомлениями (предположительно 0.1.30).
До этого можно использовать штатную настройку автоматических обновлений EDT.
Commit/push/release по результатам исследования не выполнялись.
