# Цвета Git-подписей навигатора

Дата: **05.11.2026**, локальный кандидат **0.1.27**.

EGit задаёт изменённым и игнорируемым ресурсам собственные фон/текст.
Это четыре ColorDefinition, которые читаются GitLightweightDecorator из
реестра текущей темы. Изменение фона самого Tree не меняет подложку подписи.
Прежние проверки пустого навигатора контролировали Tree, а не Git-декорации.

В установленном EGit Dark CSS задаёт фоны 47,47,47, текст изменённых объектов
114,157,186 и игнорируемых 120,120,120. Светлый stylesheet эти цвета не задаёт.
Если они остаются в preferences/реестре, получаются отдельные тёмные прямоугольники.
Исходные значения и порядок загрузки сторонних плагинов могут отличаться;
исправление явно задаёт все четыре цвета в обеих группах палитр.

| ColorDefinition `org.eclipse.egit.ui.*` | Роль |
|---|---|
| UncommittedChangeBackgroundColor | editor.background |
| UncommittedChangeForegroundColor | accent |
| IgnoredResourceBackgroundColor | editor.background |
| IgnoredResourceForegroundColor | disabled |

Идентификаторы подтверждены по plugin.xml во всех трёх тестовых EDT.
Ключи хранятся в `instance/org.eclipse.ui.workbench`, без CSS-префикса Light/Dark.
Это прямые предпочтения EGit; в отличие от прежних Dark ColorDefinitions
карты они не объявлены CSS-override. SettingCatalog учитывает исключение.
Для нестандартной legacy-темы сохраняется её префикс.

Применение, startup и точное восстановление используют существующий механизм.
Новые targets входят в original snapshot, включая отсутствие явного значения.
Ручные изменения после применения сохраняются; явное редактирование/сброс
соответствующей роли снова захватывает target по прежним правилам.
Личный фон редактора задаёт и фон Git-подписей. Ролей по-прежнему 17.
Новые production-зависимости от EGit/JGit, собственная отрисовка навигатора,
reflection и замена vendor bundles не добавлялись.

При обновлении с 0.1.26 и более ранних версий повторно нажмите «Применить»
на выбранной палитре. Это добавляет четыре новых target в существующий журнал;
сам startup намеренно не захватывает ранее неуправляемые пользовательские цвета.

## Источники и проверка

Первичные локальные источники: EGit UI **6.8.12.202605060235** в EDT 2026.1.2/1.3
и **6.8.14.202605290936** в 2026.2.2: plugin.xml, css/e4-dark_egit_prefstyle.css,
байткод GitLightweightDecorator/ChangeTrackingColorsAndFonts/DecorationHelper.
Метаданные и CSS совпали по SHA-256 во всех версиях:
[свидетельства](../testing/2026-11-05-git-labels/installed-egit-sources.json).
Также прочитаны установленные исходники Eclipse ThemeElementHelper,
ColorAndFontProviderImpl, EclipsePreferencesHandler/Helper и JFace label providers.
Закрытые реализации исследованы только для диагностики; production-код их не вызывает.

Тестовый фрагмент создаёт отдельный локальный Git-проект с чистым, изменённым
и игнорируемым файлами. Штатный декоратор создаётся через публичный extension
point org.eclipse.ui.decorators; его IDecoration выводится в SWT Tree.
Ожидается реальный фоновый IndexDiff, иначе тест не считается успешным.
Начальное проблемное состояние контролируемо задаётся значениями из Dark CSS:
это не утверждение о воспроизведении всех шагов запуска полного EDT-продукта.
Проверяются настоящие результаты EGit, raw preferences, registry и пиксели подписей.
Тестовая привязка проекта использует ConnectProviderOperation из установленного
EGit core; эта зависимость и весь fixture отсутствуют в shipping JAR.

Фактические результаты и границы — [отчёт 0.1.27](../testing/git-labels-validation.md).
