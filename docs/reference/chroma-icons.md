# Значки Visual Studio Light / Dark

Доступно начиная с версии 0.1.29.

На странице **Окно → Настройки → Внешний вид → Темы EDT** включите
**Значки Visual Studio в Навигаторе** и нажмите **Применить** или **ОК**.
Новый флаг по умолчанию выключен. Под ним показаны образцы выбранного
набора с заголовком **Visual Studio Light** или **Visual Studio Dark**. **Отмена** отбрасывает неприменённое изменение;
после Apply отмена сохраняет уже применённый выбор.

Флаг не зависит от палитры BSL и шрифта. Можно оставить штатное оформление
и использовать новые значки. При пустом журнале оформления и без личных
правок Apply флажка не перезагружает CSS и сохраняет отсутствие явных
native theme preferences. Набор автоматически следует фактической
светлой/тёмной основе EDT. Перезапуск для самого флага не нужен;
при переходе Light ↔ Dark остаётся прежнее требование перезапуска EDT.
«Восстановить исходное оформление» также выключает новые значки.

Первый этап охватывает известные базовые значки метаданных в Навигаторе
EDT: 49 рисунков
и 64 native-имени, отдельные Light/Dark SVG. Панели команд и меню пока
не охвачены. Неизвестные или уже составные изображения сохраняются
штатными; полный охват всех узлов расширений/поддержки не заявляется.

## Устройство

Менеджер находит существующий CommonNavigator по native ID
com._1c.g5.v8.dt.ui2.navigator и использует публичный
DecoratingStyledCellLabelProvider.setLabelDecorator. Сам label provider,
контекст декорации и его внутренние настройки сохраняются. Обёртка заменяет
исходную картинку перед единственным вызовом оригинального декоратора;
тот добавляет отметки и оформляет подписи штатным способом. Передаются
также prepareDecoration, события, IColorDecorator и IFontDecorator.

При отключении восстанавливается исходный объект декоратора. Если другая
компонента успела заменить его, её выбор сохраняется. При закрытии viewer
соблюдается его штатное владение декоратором; при выключении исходный
декоратор не уничтожается. Новые окна и открытие Навигатора отслеживаются
через публичные IWindowListener и IPartListener2. Пока флаг включён,
каждые 250 мс проверяется готовность существующего viewer: EDT может
создать окончательный label provider после события открытия панели.
Неизменившиеся viewer не перерисовываются. После выключения флага
наблюдение останавливается, при остановке плагина таймер удаляется.

Оригинальные Image не мутируются. Для допуска используются размеры и RGBA
ресурсов md.ui.shared после загрузки через тот же SWT Image API, что и у
WorkbenchLabelProvider. Неизвестные или уже составные исходные изображения
пропускаются. Vendor bitmap и вычисленные отпечатки не распространяются.

Собственный ресурсный кэш ограничен 49×2 изображениями. Его освобождает
остановка плагина; при выключении флага кэш сохраняется для повторного
включения без риска преждевременно уничтожить Image, удерживаемые viewer.
Native-реестры и vendor bundles не меняются. Reflection, Win32 hooks и
DLL-инъекции не применяются.

Предпочтение — icons.chroma.enabled в собственном узле плагина; отсутствие
ключа означает false. Выключение удаляет ключ. Palette/personal/font keys
остаются независимыми. Событие IThemeEngine.Events.THEME_CHANGED обновляет
декоратор через публичный workbench API.

## Происхождение и генерация

[Исследование и первичные ссылки](../research/2026-11-05-chroma-icons.md).
[Благодарности и источник набора](../../README.md#благодарности).
Полная лицензия и source.json с ревизией/контрольными суммами входят в bundle.

```text
python scripts/build-chroma-icons.py
python scripts/build-chroma-icons.py --check
```

Вторая команда проверяет, что 686 PNG воспроизводятся из SVG. Pillow нужен
только при разработке; дополнительное ПО автоматически не устанавливается.
В готовой EDT используются PNG и публичный JFace ImageDescriptor с zoom.
