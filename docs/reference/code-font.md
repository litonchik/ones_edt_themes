# Шрифт кода — 0.1.1

Исследование: 14 октября 2026, установленная EDT 2026.1.3+25, Eclipse 4.30.0,
workbench 3.131.0.v20231201-0512, Xtext UI 2.33.0.v20231121-0955, Java 17.
Пользователь подтвердил краткий дизайн до реализации.

## Подтверждённый штатный механизм

BSL Xtext editor наследует текстовый редактор Eclipse. Он получает основной шрифт из
`JFaceResources.TEXT_FONT` (`org.eclipse.jface.textfont`). Это общая настройка текстовых
редакторов, а не шрифт всего интерфейса и не отдельная CSS настройка палитры.

Источник: классы установленного `org.eclipse.ui.workbench` и исходники его source bundle:
`AbstractTextEditor.initializeViewerFont`, `WorkbenchThemeManager.currentThemeListener`,
`ThemeElementHelper.installFont/createPreferenceKey`, `ColorsAndFontsPreferencePage.performFontOk`.
BSL editor и его plugin.xml исследованы из `com._1c.g5.v8.dt.bsl.ui_23.0.1.v202609041212.jar`.
Дамп первичных исходников для исследования хранится в `.work/platform`.

Штатная страница Colors and Fonts записывает сериализованный `FontData[]` в instance node
`org.eclipse.ui.workbench`. При стандартном legacy ID `org.eclipse.ui.defaultTheme` ключ
равен `org.eclipse.jface.textfont`; для другого legacy ID — `<legacyId>.org.eclipse.jface.textfont`.
Для текстового шрифта штатной целевой EDT CSS override не используется. Сериализация и
чтение выполняются публичным `PreferenceConverter`, а не собственным форматом.

После flush плагин обновляет публичный `ITheme.getFontRegistry().put(TEXT_FONT, data)`.
Workbench пересылает событие в JFace FontRegistry; открытый текстовый редактор обновляет
шрифт по своему штатному listener. Плагин не закрывает документ, не очищает undo history,
не изменяет собственные настройки шрифта категорий подсветки.

## Независимость и восстановление

Снимок шрифта использует ту же модель транзакции `SnapshotService`, но отдельный
двухслотовый preference journal в `ru.litonchik.edt.themes/font`. Снимок цветов совместим
с 0.1.0 и не включает ключи шрифта.

`fontOriginalEffective` в собственном node хранит эффективный исходный FontData[] для
случая, когда явно заданного native значения не было. При возврате восстанавливается
точное исходное native значение или отсутствие override, а FontRegistry получает
исходный эффективный шрифт. Эта служебная запись и активный снимок очищаются после возврата.

Выбор и возврат в UI сначала изменяют только предпросмотр. Apply/OK подтверждают их;
Cancel до подтверждения отменяет выбор. Ресурс SWT Font предпросмотра принадлежит
странице и освобождается при обновлении/закрытии; шрифты реестра принадлежат Eclipse.

Явный выбор шрифта заменяет более позднюю правку штатной настройки: это запрос пользователя.
Для этого `SnapshotService.applyExplicit` сохраняет первичный original, но позволяет
перехватить ключ после manual edit. Обычное `apply` цветовых профилей сохраняет прежнюю
политику защиты ручных цветов.

При старте плагин проверяет незавершённый font journal; обычный успешный выбор не применяется
повторно поверх ручных правок. Значение уже читается штатным EDT из native preferences.

Список в UI содержит установленные масштабируемые Windows fonts; размер — целое число
пунктов от 1 до 200. Ни шрифты, ни дополнительное системное ПО не устанавливаются.
Проверка других legacy themes, сторонних CSS themes, индивидуальных token fonts и всех
редакторов с отдельными font overrides не заявляется.

## Исправление превью и списка — 0.1.2

В 0.1.1 StyledText содержал образец без StyleRange, поэтому расцветка отсутствовала.
В 0.1.2 `CodePreview` задаёт фиксированный RU/EN пример и непересекающиеся UTF-16 spans.
Страница использует роли выбранной палитры, включая base/selection colors; профиль,
шрифт и BSL checkbox обновляют только локальный preview до Apply/OK.
Это демонстрация известных категорий, не новый BSL parser. Цвета SWT принадлежат
странице, переиспользуются и освобождаются вместе с preview Font.

Пользователь воспроизвёл белую выбранную строку с белым именем в нативном Combo EDT.
Исходники целевой SWT 3.124.200 (Combo/CCombo/List/Table из установленного source bundle)
исследованы 14 октября 2026. Нативный Combo не предоставляет API раздельных цветов
выделения. Первая замена на CCombo с нативным List не прошла проверку контраста.

Итоговый `FontFamilyPicker` использует read-only Label и стрелку, а popup — Table.
Публичные EraseItem/PaintItem отключают штатную отрисовку строки и рисуют её фон и имя
одновременно. Для Darcula/Monokai используются selection roles палитры. Все методы
работают на SWT UI thread; popup закрывается при выборе, Escape, деактивации и закрытии
страницы. Enter подтверждает выделенный шрифт. Нет reflection, native win32 вызовов,
изменения системных цветов или замены vendor JAR.

Pixel probe выполняется после repaint и короткого ожидания композиции окна: снимок сразу
после открытия popup может содержать предыдущий кадр и не доказывает текущие цвета строки.
Результаты: `docs/testing/preview-validation.md`.

В 0.1.3 контрол переименован в `ReadableCombo` и переиспользуется для списка палитр.
Добавлен программный `select(int)` без события Selection; оба списка используют
одинаковую отрисовку выбранной строки и освобождают popup до локальных Color.
