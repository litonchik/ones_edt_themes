# Индикатор обновлений

Доступно начиная с версии 0.1.30.

## Поведение

При наличии новой версии в строке состояния появляется небольшой значок со стрелкой.
Подсказка указывает доступную версию. Фоновые проверки не открывают окна,
не перехватывают фокус, не запускают браузер, команды установки или звук.
Индикатор можно игнорировать, продолжая писать код и работать с агентом.

По нажатию открываются немодальные сведения. **Что нового** открывает релиз
в браузере; **Обновить** вызывает штатный мастер EDT. Эти действия выполняются
только по нажатию. Перед открытием мастера включается фиксированный HTTPS-сайт
«Темы EDT», в том числе при первоначальной установке из ZIP. Сам мастер
проверяет зависимости и получает подтверждение установки.

Страница **Окно → Настройки → Внешний вид → Темы EDT → Обновления** содержит:

- флаг **Проверять обновления в фоне и показывать индикатор**;
- **Проверить сейчас** и текст результата без всплывающего диалога;
- **Сведения об обновлении** для найденной версии, в том числе при ручной
  проверке с отключённым фоновым поиском.

По умолчанию флаг включён. Apply/OK сохраняют выбор, Cancel отбрасывает
неприменённое изменение. Отключение скрывает индикатор и отменяет задания.
Ручная проверка остаётся доступной. Восстановление палитры и шрифта
не сбрасывает настройки обновлений. Apply/OK без изменения флага не отменяют
выполняющуюся проверку и не переписывают настройки.

## Проверка версии и жизненный цикл

Источник — стабильный `repository/release.json` существующего GitHub Pages.
Версия и ссылка проверяются; разрешён только URL релиза этого проекта.
Номер сравнивается численно по major/minor/micro: qualifier установленной
сборки не создаёт ложное обновление. Опубликованная более старая версия
не предлагается вместо установленного локального кандидата.

Первая автоматическая проверка планируется через 30 секунд после запуска
сервиса. Между попытками — не меньше суток; время последней попытки
сохраняется между запусками. **Проверить сейчас** обходит этот интервал.
Уже найденная новая версия сохраняется, чтобы индикатор был доступен при
следующем запуске без ожидания сети. Успешная проверка актуальной версии
убирает старый индикатор.

Используются фоновые system Job. Одновременно не выполняются две проверки
одного монитора. Connect/read timeout — 3 секунды, тело — не больше 8192 байт,
перенаправления запрещены, чтение тела дополнительно ограничено по времени.
Нет вызовов join/syncExec и ожидания сети на UI-потоке. При отключении и stop
поколение запроса меняется: поздний ответ не публикуется и не пишет настройки.
Отмена не ждёт завершения сетевого чтения. DNS/TLS зависят от сетевого стека;
монитор не ожидает их завершения при закрытии EDT.

Ключи `updates.enabled`, `updates.lastAttempt`, `updates.latest` хранятся
в собственном instance-узле плагина; они независимы от журнала оформления.
Общие настройки автоматических обновлений EDT не изменяются.

## Неинтерактивная сеть

Учитываются явные HTTP/HTTPS-настройки прокси EDT и уже разрешённые
прокси/учётные данные в свойствах JVM. Открытые ключи проверены по исходникам
установленного org.eclipse.core.net 1.5.200. Защищённое хранилище не читается:
IProxyService.select() может загрузить пароль и вызвать запрос разблокировки.
У каждого соединения отдельный неинтерактивный Authenticator; запросы 401/407
не передаются глобальному интерактивному обработчику EDT.

При отсутствии сети, ошибках сертификата или недоступном прокси фоновая
проверка завершается тихо. Ручной результат отображается на странице настроек.
SOCKS отвергается до подключения: аутентификация SOCKS может обходить
Authenticator соединения и обращаться к глобальному обработчику Java.
Автоматическое разрешение PAC и разблокировка хранилища паролей в эту функцию
не входят. Если для сети требуется такой сценарий, проверка может быть
недоступна до настройки явного прокси; работа редактора от неё не зависит.

## Размещение и границы

Индикатор — стандартная команда с изображением в status trim,
объявленная через org.eclipse.ui.menus. Видимость и подсказка меняются
через публичную модель Eclipse и property tester. Блок скрывается,
когда обновления нет; встроенные текстовые контролы не используются.
Сведения используют отдельный modeless Shell только по выбору пользователя.
UpdateInstaller регистрирует сайт и вызывает штатную команду обновлений
только из обработчика кнопки. Фоновый сервис не содержит вызовов установщика.

[Исследование](../research/2026-11-06-update-notifications.md),
[матрица проверки](../testing/update-indicator-validation.md).
Номера будущих версий на тестовых снимках — управляемые ответы тестового
источника, а не опубликованные релизы. В рабочем плагине адрес проверки
фиксирован; JVM-флаги или пользовательские URL для подмены не добавлялись.
