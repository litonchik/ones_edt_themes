# Карта настроек EDT 2026.1.3

Дополнение 30.10.2026 / 0.1.16: карта проверена также по установленным EDT
2026.1.2+2 и 2026.2.2+21. CSS-источники BSL/QL/QL DCS/theming совпадают
побайтово. Добавлены 10 QL и 11 QL DCS RGB targets из их штатных Dark CSS
и те же 21 ключ в native snapshot; всего native-карта содержит 77 ключей.
QL Keywords/SplitterQuery соответствуют `keyword`, Strings — `string`,
Comment — `comment`, Parameters — `directive`, Function — `accent`,
Numbers — `number`, Others/Operators/Brackets/Brace — `text`.
Флаг BSL исключает только BSL-node; QL/DCS следует общей палитре.
[Компоненты, источники, runtime и restore](../testing/edt-2026-compatibility-validation.md).
Ниже сохранено описание первоначальной карты 0.1.0.

`C:\Program Files\1C\1CE\components\1c-edt-2026.1.3+25-x86_64\plugins`.

Именованные цвета имеют ключ
`<css ID>.<legacy ID если он не org.eclipse.ui.defaultTheme>.<color ID>`.
Это подтверждено `ThemeElementHelper.createPreferenceKey(cssTheme, theme, id)` в source bundle
`org.eclipse.ui.workbench.source_3.131.0.v20231201-0512.jar`.
В production нет imports внутренних классов: ключ формируется по проверенному контракту,
а применение выполняется публичным `IThemeEngine.setTheme`.

Штатный `EclipsePreferencesHandler.overrideProperty` пишет в instance preferences,
если ключ отсутствует либо `EclipsePreferencesHelper.isThemeChanged()` возвращает true.
Повторный вызов setter с тем же CSS ID устанавливает previous/current в одинаковый ID;
профиль записывается после этого. Перезагрузка штатной темы перечитывает именованные overrides.
После styling адаптер повторно сохраняет точное состояние затронутых instance keys:
это необходимо, поскольку CSS может вновь создать удалённый ключ. Таймеров перезаписи нет.

В Eclipse 4.30 `AbstractCSSEngine.convert` кэширует преобразованный SWT Color по CSS значению.
Повторное применение того же CSS ID оставляло фон реального Shell прежним, хотя ColorRegistry
уже содержал нужный RGB (это воспроизведено runtime RED-тестом). Для сброса кэша применяется
короткий переход к другой **штатной** теме с `persist=false`, затем возврат к текущей с
`persist=false`; сохраняемый ID остаётся текущим. Используются только публичные методы
IThemeEngine, без own ITheme proxy, новых ID, reflection или доступа к внутреннему resource registry.

После окончательного восстановления explicit preference values открытые текстовые редакторы
обновляются через публичный adapter `ITextOperationTarget` и `ITextViewer.invalidateTextPresentation()`.
Без этого числовой литерал оставался серым при правильном Numbers.color; runtime probe
воспроизвёл расхождение и подтвердил правильные RGB после исправления. Документы и undo history
не меняются; не используются внутренний source viewer или reflection.

При внешней смене темы listener `themeid` снимает значения управляемых цветов до выполнения
native CSS; отложенное восстановление использует это наблюдение. Поэтому ручная правка BSL
не теряется, даже если native CSS успевает заменить её своим значением до UI callback.

Снимок сохраняется перед первой мутацией. CSS/legacy IDs участвуют в том же журнале,
что и цвета. При внешней смене темы сравнение с last-applied сохраняет новый выбор,
а ручные цветовые правки освобождаются от управления до принудительного восстановления.

## Границы покрытия

Навигатор, панели свойств, вкладки, hints и общие контролы используют named colors штатной Dark.
Отдельные нативные Windows controls и специфические редакторы могут сохранять штатную Dark.
Непроверенные `BSL_Pragmas`, `Label` и категории отдельного редактора запросов в карту не включены.
Строка с запросом имеет базовый BSL string color; самостоятельная подсветка языка запроса не заявлена.

Цветовые профили не затрагивают font/keybindings/formatter/encoding или прикладные данные формы/макетов.
В 0.1.1 пользователь отдельно управляет общим текстовым шрифтом; его настройка и журнал
описаны в [шрифте кода](code-font.md).
Просмотр формы, MXL, графической схемы и макета оформления СКД проверяется отдельно;
проверка карты сама по себе не подтверждает визуальный вид этих экранов.

Фактические runtime результаты и ограничения: `docs/testing/mvp-validation.md`.
