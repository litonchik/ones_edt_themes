## Подтверждённое поведение

- При актуальной/более новой локальной версии значок отсутствует; при новой
  опубликованной версии появляется стандартный ToolItem со стрелкой.
  Проверен размер видимой области полного изображения и подсказка с номером.
- Проверка выполняется вне UI-потока. При управляемом медленном ответе
  продолжались UI timer и изменения документа BSL. Текст и modification stamp
  после ввода сохранялись; активный контрол редактора и набор окон не менялись.
- Автоматически не открывались сведения, браузер или мастер. Счётчик штатной
  команды обновления оставался нулевым до нажатия «Обновить».
- Сведения открывались только по выбору значка, Shell без APPLICATION_MODAL,
  PRIMARY_MODAL и SYSTEM_MODAL. Открытие сведений ещё не запускало мастер.
- Нажатие «Обновить» регистрировало/включало только фиксированный HTTPS-сайт
  и вызывало штатную команду EDT ровно один раз. Для её перехвата использован
  test-only handler; реальная установка новой версии в этом сценарии не выполнялась.
  Состояние менеджеров репозиториев после проверки восстановлено.
- Cancel до Apply не менял флаг; Apply отключал индикатор и задания,
  Cancel после Apply сохранял применённый выбор. Ручная проверка работала
  и при отключённом фоновом поиске. Ошибка отображалась только текстом страницы.
- При перезапуске сохранялись известная версия, опция отключения и дневной
  интервал. Повторного запроса раньше суток не было, ручная проверка обходила
  интервал. Актуальный результат очищал старую индикацию и cache.
- Два окна workbench получали согласованное состояние. Светлая и тёмная
  основа сохраняли читаемый нативный значок. Восстановление оформления
  завершалось успешно, журнал и активный профиль оставались пустыми.
- Остановка монитора во время управляемого медленного ответа не ждала сеть
  и выполнялась за миллисекунды. Отменённый ответ не публиковался и не записывал
  preferences. Повторный запуск монитора работал, stop скрывал значок.

## Сеть без запросов подтверждения

Явный HTTP-прокси настраивался через публичный IProxyService тестовой EDT;
производственный клиент использует открытые настройки без вызова защищённого
хранилища. Проверены 200/401/407, абсолютный URL прокси-запроса, non-proxy hosts,
отсутствие вызовов глобального Authenticator и точное восстановление значений
и присутствия открытых proxy preferences. SOCKS отвергался до подключения,
не достигая глобального обработчика авторизации.

Реальный bounded HTTP-клиент разбирал метаданные на Java 17 и Java 25.
Каждая целевая JVM также успешно читала настоящий HTTPS release.json с
GitHub Pages (на момент проверки он сообщал 0.1.29), не создавая окон.
Сетевые ошибки не вызывают MessageDialog и не запускают установку.
PAC и интерактивная разблокировка proxy credentials не входят в функцию.
