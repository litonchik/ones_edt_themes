# Светлые панели — локальный кандидат 0.1.22

Дата: **04.11.2026**. Исправлена неполная окраска интерфейса пяти светлых
палитр. Новые схемы, роли и personal keys не добавлялись.

## Причина и исправление

Штатная Light CSS EDT почти не связывает обычные панели с named colors.
Прежние проверки 33 значений реестра подтверждали сами RGB, но не фактические
цвета навигатора и свойств. Поэтому успешные отчёты 0.1.17–0.1.21 нельзя
считать подтверждением полной окраски светлого интерфейса.

Добавлен локальный слой SWT inline CSS для обычных контролов рабочего окна
и собственной страницы параметров. Буквальные HEX обходят ранний кэш
конвертации named colors Eclipse; после штатного переключения реестр
получает текущие явные RGB. Исходные CSS-классы и inline-стили сохраняются,
включая отсутствие значения и изменения сторонних компонентов во время работы.
Содержимое всех редакторов исключено целиком; графические Canvas панелей
также исключены, кроме обычных CLabel и Hyperlink.
[Механизм и первичные источники](../reference/light-ui.md).

Страница параметров регистрируется после создания всех контролов:
ранняя регистрация оставляла её таблицу белой при некоторых запусках EDT 2026.2.2.

CandidateUi проверяет все пять светлых схем: фактические BG/FG контейнеров
навигатора и свойств, Tree навигатора, Table/Tree/Text/Combo/Button/Label,
Link/Hyperlink и disabled Label в тестовом view, выбранные вкладки.
Проверяются поздно созданный Tree, новое рабочее окно, личный `panel` и сброс
роли, собственная таблица параметров. BSL background/keyword, текст и
modification stamp сохраняются. Произвольный тестовый редактор и BSL не
получают UI-маркеров; отдельный refresh слоя сохраняет явно заданные цвета
Tree и Canvas внутри редактора. Это структурная проверка исключения содержимого,
а не проверка полного настоящего конструктора формы или макета.

Дополнительно намеренно добавляются сторонние CSS-класс и inline-стиль,
после чего принудительно выполняется ещё один UI refresh и переход к Dark:
сторонние изменения сохраняются, собственные маркеры снимаются.

CandidateUiRestart подтверждает сохранённую Noctis Lux после новой JVM,
повторяет UI-матрицу, проверяет точный restore preferences и фактических
штатных RGB Tree, отсутствие исходного CSS-класса/inline-стиля, неизменность
настройки шрифта. Внешний переход к native Dark освобождает профиль.

CandidateAllSurfaces повторяет прежнюю матрицу **всех 16 палитр**, поскольку
изменён общий механизм: BSL, обычный текст, QL, QL DCS, два QlEditor конструктора,
BSL compare/merge и точное восстановление. Полный metadata query wizard
не запускался; BSL merge panes по-прежнему требуют переоткрытия для новой подсветки.

## Воспроизведение

В отдельных копиях EDT с изолированными workspace/home/appdata:
`p2-test Install` → `build-workbench-probe` → `CandidateUi` →
`CandidateUiRestart` → `CandidateAllSurfaces -ProfileId noctis-lux`.
Для 2026.2.2 у всех probe/p2 шагов используется Axiom JDK 25,
для 2026.1.x — JDK 17; сам release собран с Java 17.
Для галереи: `CandidateGalleryPrepare -ProfileId noctis-lux` →
новая JVM → `CandidateUiGallery`. Завершение всегда отдельной фазой
Cleanup → Reconcile → p2 Uninstall → Audit.
